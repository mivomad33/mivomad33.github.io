# 변경 6: 완성한 프로젝트를 포트폴리오와 글로 넣는 스킬(add-project)

- 상태: 완료(2026-10-24). 사용자 검토를 통과해 main에 squash merge했다.
- 브랜치: `change/6-add-project-skill`

## 배경

- Senseful을 포트폴리오에 넣고 만든 과정을 글로 썼다(2026-10-23). 사용자가 앞으로 프로젝트를 끝낼 때마다 같은 일을 하게 되므로, 프로젝트 경로를 넘기면 포트폴리오 항목과 글을 만드는 스킬을 만들자고 했다(2026-10-24).
- 명세서(`write-spec`)는 쓰지 않았다(2026-10-24, 추천안·사용자 승인). 한 세션에서 대화하며 끝낼 크기이고, 스킬 파일 자체가 지침 문서라 명세서와 내용이 겹치며, 스킬의 품질은 실제 프로젝트로 시험 실행해야 확인할 수 있기 때문이다.

## 요구사항

### 해야 하는 것

- 이 저장소에서 `/add-project <프로젝트 경로>`로 부르면, 그 프로젝트의 포트폴리오 항목(`src/data/portfolio.yaml`)과 만든 이야기 글(`src/content/blog/<slug>/`의 `ko.md`, `en.md`, `images/`)을 만든다. 실행할 때 포트폴리오만, 글만 고를 수도 있다.
- 글은 코드뿐 아니라 프로젝트의 결정 기록(문서, 메모, 명세서, 평가 결과)에서 확인한 사실로 쓴다. 지어낸 동기나 숫자를 넣지 않는다.
- 시작할 때 사람이 정할 것을 묻고, 글의 중심 이야기와 섹션 목록(구성안)을 함께 보여 한 번에 확인받는다. 그 뒤에는 검증까지 끝내고 보고한다.
- 화면 이미지는 Claude가 내장 브라우저로 찍는다.
- 커밋·브랜치·머지는 이 저장소의 `CLAUDE.md`를 따른다(공개 전에는 작업 브랜치, 8단계 완료 뒤 콘텐츠는 main에 바로 push).

### 하지 않는 것

- 원본 프로젝트의 파일(README 등)은 바꾸지 않는다. 저장소마다 브랜치·머지 규칙이 달라 범위를 넓히지 않는다. 필요하면 보고에서 알린다.
- Senseful 글의 섹션 구성을 틀로 쓰지 않는다. 매번 같은 구성이면 글이 비슷해지기 때문이다. 문체와 원칙만 따른다.

## 결정(2026-10-24, 모두 추천안·사용자 승인)

- 위치: 이 저장소의 `.claude/skills/add-project/`. 이 블로그의 데이터 형식과 글 폴더 구조에 묶인 스킬이라, 형식이 바뀔 때 같은 커밋에서 함께 고치고 git으로 관리하기 위해서다. 뺀 안: 다른 작업 흐름 스킬처럼 `~/.claude/skills/`(이 블로그의 경로와 형식을 스킬에 적어야 하고 버전 관리가 안 된다).
- 이름: `add-project`. 뺀 안: `write-project-post`(포트폴리오가 중심인 일인데 글 쓰기만 드러난다).
- 범위: 기본은 포트폴리오와 글을 함께 만들고, 하나만 고를 수 있다. 뺀 안: 항상 둘 다(글 없이 포트폴리오만 넣을 작은 프로젝트에 쓸 수 없다).
- 이미지: Claude가 운영 사이트나 로컬 개발 서버를 찍고 합쳐 압축한다. 찍을 수 없는 화면만 사용자에게 받는다. 뺀 안: 사용자가 제공(매번 직접 찍어야 한다), 실행할 때마다 묻기.
  - 만들면서 정한 것: 내장 브라우저의 스크린샷은 파일로 남지 않아, 화면 고르기와 확인은 내장 브라우저로 하고 파일 저장과 여러 장 합치기(나란히 놓은 HTML을 찍는다)는 Playwright CLI로 한다. 이 저장소에 이미지 도구 의존성을 더하지 않기 위해서다.
- 원본 README에 글 링크 더하기: 하지 않는다(위 "하지 않는 것").
- GitHub 링크: mivomad33 계정의 공개 저장소만 바로 링크한다. 다른 계정이거나 비공개면 묻고, 답이 없으면 넣지 않는다. 다른 계정 이름이 공개 사이트에 드러나지 않게 하기 위해서다([memory.md](../memory.md)의 커밋 작성자 항목). 뺀 안: 공개라면 계정과 관계없이 링크.
- 확인 시점: 질문과 구성안을 한 번에. 뺀 안: 질문만(방향을 다 쓴 뒤에야 본다), 한국어 초안까지 확인(멈추는 곳이 하나 더 는다).
- 시험 실행: wonbook. mivomad33 계정의 공개 저장소이고 결정 기록 문서가 있어 Senseful과 비슷한 조건이다. 결과는 별도 브랜치에 두고 넣을지는 사용자가 정한다.

## 진행 계획

1. 스킬 작성 — 상태: 완료(2026-10-24)
2. wonbook으로 시험 실행 — 상태: 완료(2026-10-24)
   - 결과(글 `building-wonbook`, 포트폴리오 항목, 이미지)는 사용자가 화면으로 읽고 승인해 함께 main에 넣었다(2026-10-24).
   - 확인 결과: `pnpm verify` 통과. 외부 링크 3개 200. 개발 서버에서 두 언어의 글 보기(이미지 1626×1145가 webp로 바뀌어 나옴), 블로그 목록, 포트폴리오, 홈을 봤고, 만든 이야기 링크가 한국어 `/blog/building-wonbook/`, 영어 `/en/blog/building-wonbook/`로 간다. 375px 폭에서 가로 스크롤이 없다.
   - 시험 중 사용자 답: 중심 이야기는 추천안(정리 규칙 + 공개 섹션), 쓰던 가계부 서비스 이름은 쓰지 않음, 비공개 사실은 "알아서 판단"(결정·이유·비용 예상은 쓰고, 한도 숫자·최악 비용·테스트 수는 뺐다).
   - 시험에서 나와 스킬에 반영한 것:
     - 근거 없는 이유를 덧붙인 문장이 하나 나왔다(이체를 짝짓지 않은 이유). 사실 대조에서 잡아 지웠고, 이유도 사실로 대조하라는 규칙을 더했다.
     - wonbook은 실사용 단계(성공 기준 확인)가 아직 진행 전이었다. 진행 상태를 살펴보고 이룬 것처럼 쓰지 않는 규칙을 더했다. 처음에는 "아직 남은 것" 섹션으로 썼으나, 사용자가 필요 없다며 지웠고 남은 일을 따로 쓰지 않는 것으로 정했다(2026-10-24).
     - wonbook은 README에 쓰던 서비스 이름을 쓰지 않기로 정해 두었다. 원본이 공개 문구에 대해 정한 것을 따르는 규칙을 더했다.
     - 비공개 사실의 판단을 맡겼을 때의 기준을 더했다.
     - Playwright: pnpm 프로젝트에서는 `@playwright/test`를 불러야 했고, 브라우저 언어를 맞추지 않으면 날짜 입력이 영어로 찍혔다. 찍기·합치기 값(폭, 배율, 배치)을 적었다.
     - 개발 서버에서 본문 이미지가 지연 로딩으로 빈칸처럼 보였다. 확인 방법을 적었다.
3. 사용자 검토 — 상태: 완료(2026-10-24). 사용자가 개발 서버에서 wonbook 글을 읽고 "아직 남은 것" 섹션을 지우게 한 뒤 통과시켰다.
