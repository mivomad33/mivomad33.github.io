- 상태: 완료(2026-10-23). 사용자 검토를 통과해 main에 squash merge했다.
- 브랜치: `change/localized-internal-links`

## 배경

- Senseful을 포트폴리오에 넣고 만든 과정을 블로그 글(`/blog/building-senseful/`)로 썼다(2026-10-23). 사용자가 포트폴리오 항목에서 이 글로 가는 링크를 달자고 했다.
- 데이터 파일(프로필, 포트폴리오)의 링크 주소는 언어마다 하나다. 그래서 사이트 안 주소 `/blog/building-senseful/`을 적으면 영어 페이지에서 눌러도 한국어 글로 갔다. [변경 1](1-english-version.md)에서 두 언어를 더할 때 데이터 파일의 사이트 안 링크는 쓰는 곳이 없어 다루지 않았다.

## 요구사항

### 해야 하는 것

- 데이터 파일의 사이트 안 링크(`/`로 시작)를 페이지 언어의 주소로 연다. 영어 페이지에서는 `/en/...`으로 간다.
- 외부 주소(`https://`)와 `mailto:`는 그대로 둔다.
- Senseful 포트폴리오 항목에 블로그 글 링크를 단다.

### 하지 않는 것

- 링크 모양은 바꾸지 않는다(다른 링크와 같은 포트폴리오 카드의 링크다). 그래서 시안 단계를 두지 않았다.
- 글 본문(md)의 사이트 안 링크는 다루지 않는다. 글은 언어마다 파일이 따로 있어 그 언어의 주소를 직접 적으면 된다.

## 설계

- 데이터 파일에는 사이트 안 주소를 기본 언어(한국어) 경로로 한 번만 적는다(예: `/blog/building-senseful/`). 언어마다 주소를 따로 적게 하지 않은 이유는, 두 언어의 주소가 항상 접두어(`/en`)만 다르기 때문이다.
- `src/lib/i18n.ts`의 `localizeLink`가 링크명은 그 언어의 값으로 꺼내고, `/`로 시작하는 주소에는 `localePath`로 언어 접두어를 붙인다. 프로필(`getProfile`)과 포트폴리오(`getPortfolio`)가 같이 쓴다. 두 곳에 같은 변환이 따로 있던 것을 이 함수 하나로 모았다.
- 링크명은 "만든 이야기" / "Write-up"으로 정했다.

### 바뀐 문서

- design.md: [데이터 파일 형식](../design.md#데이터-파일-형식)의 링크 `url` 설명(사이트 안 주소는 기본 언어 경로로 적고, 페이지 언어에 맞게 바뀐다)
