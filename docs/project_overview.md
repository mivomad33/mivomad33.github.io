# 프로젝트 개요

## 목표

- 프로필, 포트폴리오, 블로그를 담은 개인 웹사이트(mivomad33.dev)를 만든다.
- 이유: 내 프로필, 포트폴리오, 블로그를 관리·운영할 사이트가 없어서 활동한 결과물이 남지 않는다. 활동한 결과물을 남겨서 언제든 활용할 수 있게 하기 위해서다.
- 만드는 사람: 8년 차 웹 개발자(온라인 활동명 mivomad33), Claude Code를 활용해 개발한다.
- 대상: 채용 담당자, 사업 파트너나 고객, 개발자 독자, 일반 커뮤니티 등 누구나. 블로그 글을 검색해서 들어오는 방문자도 있다.

## 성공의 모습

- 프로필, 포트폴리오, 블로그가 방문자에게 잘 전달된다.
- 블로그 글은 md 파일을 추가하고 push하면 자동으로 배포된다.
- 프로필과 포트폴리오도 데이터 파일만 고치면 사이트에 반영된다.

## 원칙과 제약

- 정적 사이트로 개발해 GitHub Pages로 호스팅하고, 이미 확보한 mivomad33.dev 도메인을 연결한다.
- 블로그는 웹에서 입력하지 않고, md 파일을 빌드해 정적 콘텐츠로 만들어 배포한다.
- 검색으로 들어오는 방문자가 있으므로 검색 노출(SEO)을 고려한다.
- 사이트 언어는 한국어만 사용한다.
- 디자인은 미니멀하게 한다.
- 마감 일정은 없다.

## 범위

### 하는 것

- 홈: 최근 포트폴리오와 최근 블로그 글을 몇 개씩 보여 주고, 각 전체 목록으로 안내한다. 페이지 구성은 [design.md](design.md#페이지-구성과-url)에 있다.
- 소개 페이지: 프로필을 보여 준다.
- 포트폴리오 페이지: 항목마다 명칭, 설명, 링크 목록(링크명, 링크 주소)을 데이터 파일에 적으면 카드 형태로 표시한다.
  - 명칭과 설명은 필수, 링크는 0개 이상이다(공개 링크가 없는 항목도 넣을 수 있게 하기 위해서다).
  - 데이터 파일에 적은 순서대로 표시한다(별도 순서 값을 두면 관리할 것이 늘어나기 때문이다).
  - 기간, 기술 스택, 썸네일 등 다른 항목은 지금 넣지 않고 필요해지면 추가한다(항목마다 채워야 해서 관리가 번거로워지기 때문이다).
  - 데이터 파일 형식과 필드는 [design.md](design.md#데이터-파일-형식)에 있다.
- 블로그: 글 목록과 글 보기. 개발, 사업 관련 활동 기록을 게시한다.
- SEO 기본: 메타 태그, sitemap 등.
- md 파일 push 시 자동 빌드·배포.

### 하지 않는 것

- 위 범위 밖의 기능(댓글, 방문 통계, RSS, 태그/카테고리, 검색, 다크 모드, 문의 폼 등)은 지금 계획에 없다. 사이트를 사용해 보면서 필요할 때 추가한다.

## 현재 상태

- 단계 구성과 진행 상태는 [진행 계획](plan.md)에 있다.
- 기술 스택: Astro, Tailwind CSS, pnpm 기반으로 정했다(1단계 완료). 확정 내용은 [설계 문서](design.md#기술-스택)에 있다.
- 공통 설계: 페이지 구성(홈, 포트폴리오, 소개, 블로그), URL, 데이터 파일 형식, 디렉터리 구조, 코드 규칙, 테스트 전략을 정했다(2단계 완료). 확정 내용은 [설계 문서](design.md)에 있다.
- UI 디자인: 개발자 모노형(고정폭 기호·날짜, 초록 강조색)으로 정하고 색·글꼴·간격·날짜 형식 등을 공통 UI로 확정했다(3단계 완료). 확정 내용은 [설계 문서](design.md#공통-ui)에 있다.
- 기반과 배포: 프로젝트 골격, 공통 레이아웃(헤더·푸터), 검증 명령을 만들고, main에 push하면 검증·빌드를 거쳐 https://mivomad33.github.io/ 로 자동 배포된다(4단계 완료). 공개 전이라 검색 엔진 수집은 막혀 있다(noindex, robots.txt).
- 홈·포트폴리오·소개: 데이터 파일(`src/data/profile.yaml`, `portfolio.yaml`)만 고치면 세 페이지에 반영되고, 필수 항목이 빠지거나 형식이 틀리면 빌드가 실패한다(5단계 완료). 포트폴리오는 아직 샘플이다. 다음은 6단계(블로그)다.
