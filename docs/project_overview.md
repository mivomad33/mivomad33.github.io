# 프로젝트 개요

## 목표

- 프로필, 포트폴리오, 블로그를 담은 개인 웹사이트(mivomad33.dev)를 만든다.
- 이유: 내 프로필, 포트폴리오, 블로그를 관리·운영할 사이트가 없어서 활동한 결과물이 남지 않는다. 활동한 결과물을 남겨서 언제든 활용할 수 있게 하기 위해서다.
- 만드는 사람: 8년 차 웹 개발자(온라인 활동명 mivomad33), Claude Code를 활용해 개발한다.
- 대상: 채용 담당자, 사업 파트너나 고객, 개발자 독자, 일반 커뮤니티 등 누구나. 블로그 글을 검색해서 들어오는 방문자도 있다.

## 성공의 모습

- 프로필, 포트폴리오, 블로그가 방문자에게 잘 전달된다.
- 블로그 글은 md 파일을 추가하고 push하면 자동으로 배포된다.
- 프로필과 포트폴리오도 데이터 파일만 고치면 사이트에 반영된다.

## 원칙과 제약

- 정적 사이트로 개발해 GitHub Pages로 호스팅하고, 이미 확보한 mivomad33.dev 도메인을 연결한다.
- 블로그는 웹에서 입력하지 않고, md 파일을 빌드해 정적 콘텐츠로 만들어 배포한다.
- 검색으로 들어오는 방문자가 있으므로 검색 노출(SEO)을 고려한다.
- 사이트 언어는 한국어만 사용한다.
- 디자인은 미니멀하게 한다.
- 마감 일정은 없다.

## 범위

### 하는 것

- 프로필 페이지: 프로필과 포트폴리오를 한 페이지에 함께 넣는다.
- 포트폴리오: 항목마다 명칭, 설명, 링크 목록(링크명, 링크 주소)을 데이터 파일에 적으면 카드 형태로 표시한다.
  - 명칭과 설명은 필수, 링크는 0개 이상이다(공개 링크가 없는 항목도 넣을 수 있게 하기 위해서다).
  - 데이터 파일에 적은 순서대로 표시한다(별도 순서 값을 두면 관리할 것이 늘어나기 때문이다).
  - 기간, 기술 스택, 썸네일 등 다른 항목은 지금 넣지 않고 필요해지면 추가한다(항목마다 채워야 해서 관리가 번거로워지기 때문이다).
  - 데이터 파일 형식(JSON/YAML, 필드 이름)은 프레임워크를 정한 뒤 `docs/design.md`에 정한다.
- 블로그: 글 목록과 글 보기. 개발, 사업 관련 활동 기록을 게시한다.
- SEO 기본: 메타 태그, sitemap 등.
- md 파일 push 시 자동 빌드·배포.

### 하지 않는 것

- 위 범위 밖의 기능(댓글, 방문 통계, RSS, 태그/카테고리, 검색, 다크 모드, 문의 폼 등)은 지금 계획에 없다. 사이트를 사용해 보면서 필요할 때 추가한다.
