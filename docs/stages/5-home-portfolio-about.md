# 5단계: 홈·포트폴리오·소개 페이지

목적, 끝난 상태, 하위 단계는 [진행 계획](../plan.md)의 5단계를 따른다. 이 문서는 이 단계에서만 쓰는 구체적인 선택과 이유를 담고, 여러 단계가 따를 것은 [design.md](../design.md)에 적는다.

- 상태: 완료(2026-10-20). 하위 단계 1·2 모두 사용자 검토 통과

## 하위 단계 1: 포트폴리오 데이터와 포트폴리오 페이지

### 로더

- 4단계의 프로필 로더(`yaml-object-loader.ts`)를 `src/lib/yaml-loader.ts`로 바꾸고, 파일 읽기·검증·저장·개발 서버 감시를 공통 함수 하나로 모았다. 프로필용 `yamlObjectLoader`와 포트폴리오용 `yamlArrayLoader`는 "읽은 값을 항목 목록으로 바꾸는 부분"만 다르다.
  - 같은 문제(기본 로더가 읽기 오류를 숨김)를 피하는 코드가 두 벌 생기지 않게 하기 위해서다.
- `yamlArrayLoader`:
  - `id`는 배열의 위치를 1부터 센 값이다. 스키마 오류 메시지에 `portfolio → 1`처럼 나오므로, 사람이 세는 방식(첫 항목이 1)과 맞췄다.
  - 컬렉션이 돌려주는 순서는 문서로 보장되지 않는다. 그래서 순서를 저장 순서에 기대지 않고, 가져오는 함수가 `orderById`로 `id`의 숫자 순서로 정렬한다(문자열로 정렬하면 `10`이 `2`보다 앞에 온다).
  - 배열이 아니면(객체, 빈 파일) 빌드를 멈추고, 항목이 없으면 `[]`를 적으라고 안내한다. 빈 파일을 항목 0개로 읽지 않는 것은, 파일 내용을 실수로 지운 것과 일부러 비운 것을 구분하기 위해서다.
  - 항목이 객체가 아니면(예: `- 이름만`) 몇 번째 항목인지 알려 주고 빌드를 멈춘다.
- 공통: 모든 항목을 검증한 뒤에 저장소를 바꾼다. 개발 서버에서 파일을 고치다 오류가 나면 일부 항목만 바뀐 상태가 남지 않고 이전 데이터가 유지된다.

### 데이터와 화면

- 스키마: `name`, `description`(필수, 빈 문자열 불가), `links`(0개 이상, `linkSchema`). `strictObject`라 다른 키가 있으면 실패한다.
- 가져오기: `src/lib/portfolio.ts`의 `getPortfolio()`(전체, 파일 순서)와 `getRecentPortfolio()`(앞에서 3개, 하위 단계 2의 홈에서 쓴다).
- 샘플 데이터: 시안의 예시 4개를 옮겼다(링크 2개·0개·1개 항목, 긴 설명). 4번째 항목은 줄바꿈되는 긴 명칭을 보려고 시안보다 명칭과 설명을 늘렸다(모바일 폭에서 두 줄이 된다). 8단계 전에 실제 내용으로 바꾼다.
- 컴포넌트:
  - `PortfolioCard`: 카드 하나. 명칭의 제목 단계(`headingLevel`)를 받는다. 포트폴리오 페이지는 `h2`, 홈은 영역 제목(`h2`) 아래이므로 `h3`다(시안과 같다).
  - `PortfolioList`: 카드 목록(`ul`과 카드 사이 간격). 포트폴리오 페이지와 홈이 같은 간격을 쓰므로 목록도 컴포넌트로 뽑았다.
- 빈 배열이면 `/portfolio/`에 "아직 항목이 없습니다."를 보여 준다([design.md](../design.md#페이지-구성과-url)).
  - 이때 빌드와 개발 서버가 `The collection "portfolio" does not exist or is empty` 경고를 낸다. Astro가 빈 컬렉션에 내는 경고라 끌 수 없으며, 빌드는 성공하고 정상 동작이다.

### 확인 결과(2026-10-20)

- `pnpm verify` 통과.
- 이전 빌드 데이터(`node_modules/.astro/data-store.json`)가 있는 상태에서 아래를 하나씩 넣으면 모두 빌드가 실패했다(복원 뒤 다시 성공).
  - 필수 항목(`description`) 누락, 정해지지 않은 키(`link`), 형식이 틀린 링크(`http://`), YAML 문법 오류, 배열이 아닌 파일(객체), 빈 파일, 객체가 아닌 항목
  - `profile.yaml`의 YAML 문법 오류(로더를 공통으로 바꾼 뒤에도 실패)
- 항목 순서를 뒤집으면 화면 순서도 뒤집혔고, 항목 12개에서도 1~12 순서대로 나왔다. 빈 배열은 빌드가 통과하고 안내 문구가 보였다.
- 빌드 미리보기의 `/portfolio/`를 시안과 비교했다. 목록 간격(28px), 카드의 선(2px, 구분선 색)·안쪽 여백(16px)·줄 사이(6px), 명칭·설명·링크의 글자 크기·줄 간격·색이 시안과 같았다. 모바일(375px)에서 가로 스크롤이 없다.

### 검토에서 고친 것(2026-10-20)

- 별도 세션(서브에이전트)이 산출물만 보고 검토했다. 결함은 없었고, 아래 문서 보완만 반영했다.
  - 빈 배열에서 나는 Astro 경고가 정상이라는 설명을 추가했다.
  - 샘플 데이터 설명을 실제와 맞췄다(4번째 항목은 시안보다 늘렸다).
  - design.md와 이 문서에 겹쳐 있던 정렬 이유를 이 문서에만 남겼다.
- 그대로 둔 것:
  - 데스크톱에서는 긴 명칭이 한 줄로 보인다. 줄바꿈 모양은 모바일 폭에서 확인한다.
  - 개발 서버에서 아주 빠르게 연달아 저장하면 다시 읽기가 겹칠 수 있다. 실제 영향이 거의 없고 프로필 로더와 같은 구조라 두었다.

## 하위 단계 2: 소개 페이지와 홈

### 소개 페이지

- 시안처럼 페이지 제목에 활동명, 그 아래 한 줄 소개(흐린 글자색, 제목과의 간격을 좁힌다), 이메일·링크를 정의 목록(`dl`)으로 둔다.
- 링크가 0개면 "링크" 줄을 숨긴다. 시안은 빈 줄을 그대로 두지만, 내용 없는 이름표만 남기 때문이다.
- 이름표 뒤의 `:`는 시안의 CSS(`::after`) 대신 글자로 넣었다. Tailwind 클래스만으로 쓰기 위해서다.
- 이메일·링크의 2칸 격자는 임의 값(`grid-cols-[...]`)이 코드 규칙에 어긋나므로 `global.css`에 `grid-cols-label` 유틸리티로 정의했다. 6단계 글 목록 항목(날짜·제목)도 넓은 화면에서 같은 격자를 쓸 수 있다(`sm:grid-cols-label`). 이 방식(이름 붙인 유틸리티)은 design.md 코드 규칙에 적었다.

### 홈

- 한 줄 소개와 영역들을 한 격자에 간격 14(`gap-14`)로 쌓는다(한 줄 소개는 이후 홈에서 뺐다. [design.md](../design.md#페이지-구성과-url) 참고). 시안의 "소개 아래 간격"과 "영역 사이 간격"이 같은 값이라, 6단계에서 최근 글 영역을 넣어도 간격이 맞고, 영역이 모두 숨겨져도 소개 아래에 빈 여백이 남지 않는다.
- `HomeSection`: 영역 제목(`## ` + 제목)과 "전체 보기 →" 링크, 그 아래 목록(slot). 6단계의 최근 글도 쓴다. 영역을 숨기는 판단(0개)은 페이지가 한다.
- 최근 포트폴리오는 `getRecentPortfolio()`(앞에서 3개)와 하위 단계 1의 `PortfolioList`(명칭은 `h3`)로 보여 준다.

### 확인 결과(2026-10-20)

- `pnpm verify` 통과. 빌드한 CSS에 `grid-cols-label`이 만들어진 것을 확인했다.
- 빌드 미리보기의 홈과 소개를 시안과 비교했다.
  - 홈: 소개 아래 간격(56px), 영역 머리의 아래 간격(24px)·정렬(baseline), 영역 제목(15px, 굵게), "전체 보기"(13px, 흐린 글자색)가 시안과 같았다.
  - 소개: 한 줄 소개의 간격(-24px, 40px)·색, 격자 칸 폭·간격(24px, 12px)·글자 크기(13px), 이름표·링크 색이 시안과 같았다.
  - 모바일(375px)에서 두 페이지 모두 가로 스크롤이 없다.
- 데이터 파일을 바꿔 빌드한 결과:
  - 포트폴리오 4개: 홈에 앞의 3개. 맨 위에 새 항목을 넣으면 홈과 포트폴리오 페이지에 새 항목이 맨 앞에 나온다.
  - 2개: 홈에 2개. 빈 배열: 빌드가 통과하고 홈에 영역이 없다.
  - 프로필의 활동명·소개·이메일을 바꾸면 홈·소개(소개는 본문, 활동명·이메일은 헤더·푸터 포함)에 반영됐다. 링크를 빈 배열로 하면 소개의 "링크" 줄이 사라진다.

### 검토에서 고친 것(2026-10-20)

- 별도 세션(서브에이전트)이 산출물만 보고 검토했다. 결함은 없었고, 아래를 반영했다.
  - 홈: 한 줄 소개의 아래 여백(`mb-14`)과 영역 래퍼를 한 격자 간격으로 합쳤다. 포트폴리오가 0개일 때 소개 아래에 빈 여백과 빈 `div`가 남았기 때문이다.
  - design.md: 디렉터리 구조의 `global.css` 설명에 `@utility`를 더했다. 코드 규칙에서는 지금 있는 유틸리티 목록을 빼고 `global.css` 주석을 보게 했다(문서와 코드가 어긋나지 않게).
- 그대로 둔 것: 링크 0개면 "링크" 줄 숨김, 이름표의 `:`를 글자로 넣은 것(사용자 승인), 홈에 `h1`이 없는 것(시안 구조. 7단계에서 화면에 보이지 않는 `h1`을 넣었다).
